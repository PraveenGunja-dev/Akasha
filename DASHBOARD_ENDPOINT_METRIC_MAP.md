## Snapshot Priority

The baseline snapshot set should cover, in order:

1. `/api/dashboard/summary?nocache=true` for all portfolios and one deterministic portfolio filter.
2. `/api/dashboard/capacity-overview` for all portfolios and the same filter.
3. `/api/project-360` with cache bypass plus two detail calls: one fully matched project and one mapping without P6.
4. `/api/financials?nocache=true`, `/api/financials/details?nocache=true`, `/api/logistics?nocache=true`, and `/api/logistics/details?nocache=true` at global and one project scope.
5. `/api/pmag/dashboard` under a frozen clock.
6. Quality overview, contractor, representative project, NC list, and trends under the same frozen clock.
7. TC regional endpoints plus structured outputs from `tc_get_project_lines` for a representative mapped project.
8. Frontend-derived Risk Command Center and Capacity Overview metric snapshots calculated from the frozen API responses, without browser screenshots as the source of truth.

## Missing-P6 Compatibility Boundary

Missing-P6 schedule display preserves the approved `/api/dashboard/summary` compatibility fallback: `On Track`, progress `0`, and inclusion in the on-track aggregate. Snapshot it as `legacy_surface_behavior`, not as a source-backed shared-service result. All non-P6 endpoint facts remain independently in scope.
